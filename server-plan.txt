西域果铺 — 后端架构设计
=======================

技术栈
------
| 层        | 选型                  | 理由                                       |
|-----------|----------------------|--------------------------------------------|
| 框架      | Spring Boot 2.7.x/3.x | Java 生态最主流                             |
| ORM       | MyBatis-Plus          | CRUD 基本不用写 SQL，复杂查询写 XML          |
| 数据库    | MySQL 8.0             | 订单、用户、商品都是关系型数据，事务刚需     |
| 缓存      | Redis                 | 微信 access_token 缓存、热门商品缓存、限流   |
| 认证      | Spring Security + JWT | 后台用账号密码登录；小程序用微信 openid      |
| 支付      | 微信支付 API V3       | 小程序支付、退款                            |
| 文件存储  | 腾讯云 COS            | 商品图片、用户头像                          |
| 接口文档  | Knife4j (Swagger)     | 前端对接不用猜字段                          |
| 部署      | 腾讯云轻量应用服务器    | 2核4G 跑 Spring Boot + MySQL，≈70元/月      |
| 数据库管理 | Navicat               | 本地 localhost:3306                         |
| CI/CD     | 暂不需要               | 单人项目，手动部署即可                       |


数据库设计（8张表）
==================
10 张表，已从 products.js 全部导入初始数据：

表	说明	初始数据
category	商品分类	3 条（尝鲜/珍品/好物）
product	商品	13 款产品全部入库
cost_breakdown + cost_breakdown_item	成本透明	开心果 + 小白杏（主表+明细）
scorecard + scorecard_dim	6星评分卡	开心果 + 小白杏干 + 无花果干（主表+维度）
package_def + package_product	套餐	尝鲜包 / 尊享礼盒 / 家庭囤货装
user	用户	空（注册时写入）
address	收货地址	空
order_head + order_item	订单	空
sys_user	后台管理员	admin / admin123


核心表：

  user                   订单表里关联的用户
  ├── id (bigint PK)
  ├── openid (微信唯一标识)
  ├── nickname / avatar
  ├── phone
  └── created_at

  address                收货地址
  ├── id
  ├── user_id (FK → user)
  ├── name / phone / province / city / district
  ├── detail (详细地址)
  └── is_default (是否默认)

  category               商品分类
  ├── id
  ├── name (尝鲜精选/西域珍品/口碑好物)
  ├── code (trial/premium/bestseller)
  ├── theme_color (blue/amber/green → 前端对应色系)
  └── sort_order

  product                商品
  ├── id
  ├── category_id (FK)
  ├── name / price / unit / image
  ├── badge / tags (JSON)
  ├── desc / highlight / extra
  ├── stock (库存)
  ├── is_on_sale / sort_order
  └── cost_detail (成本明细 JSON → 前端透明展示用)

  order_head             订单主表
  ├── id + order_no (唯一订单号)
  ├── user_id (FK) + address_id
  ├── total_amount (实付金额)
  ├── status (UNPAID/PAID/SHIPPED/COMPLETED/CANCELLED)
  ├── wx_transaction_id (微信支付流水号)
  ├── remark (用户备注)
  ├── paid_at / shipped_at / completed_at
  └── created_at

  order_item             订单明细
  ├── id
  ├── order_id (FK) + product_id (FK)
  ├── product_name (冗余，防止商品改名后历史订单混乱)
  ├── price (下单时单价)
  ├── quantity
  └── subtotal

辅助表：

  sys_user               后台管理员
  ├── id / username / password (BCrypt)
  └── role (ADMIN / OPERATOR)

  scorecard              商品评分卡(6星)
  ├── id / product_id
  └── 6个维度分数字段


API 设计
========

公开接口（网页 + 小程序调用）：
  GET    /api/products              商品列表（分页+按分类筛选）
  GET    /api/products/{id}         商品详情
  GET    /api/cost-breakdown        成本透明数据
  GET    /api/scorecards            6星评分卡
  GET    /api/packages              套餐数据

小程序端（需微信登录）：
  POST   /api/wx/login              微信登录（code → openid → JWT）
  GET    /api/user/addresses        我的地址列表
  POST   /api/user/addresses        新增地址
  PUT    /api/user/addresses/{id}   编辑地址
  DELETE /api/user/addresses/{id}   删除地址
  POST   /api/orders                创建订单
  GET    /api/orders                我的订单列表
  GET    /api/orders/{id}           订单详情
  POST   /api/orders/{id}/cancel    取消订单
  POST   /api/wx/pay                发起微信支付
  POST   /api/wx/pay-callback       微信支付回调（更新订单状态）

管理后台（JWT 账号密码登录）：
  POST   /api/admin/login           管理员登录
  GET    /api/admin/orders          订单管理（分页、按状态筛选）
  PUT    /api/admin/orders/{id}/status  改状态（发货/完成）
  GET    /api/admin/products        商品管理
  POST   /api/admin/products        新增商品
  PUT    /api/admin/products/{id}   编辑商品
  PUT    /api/admin/stock/{id}      改库存


下单流程
========

  小程序端                          后端                            微信
     │                               │                               │
     │──① 选品加购──────────────────▶│                               │
     │──② 提交订单──────────────────▶│                               │
     │   (商品+地址+备注)              │──③ 生成订单(状态=UNPAID)       │
     │                               │──④ 调用微信统一下单──────────▶│
     │                               │◀─── 返回 prepay_id ──────────│
     │◀─⑤ 返回支付参数──────────────│                               │
     │──⑥ 调起微信支付─────────────────────────────────────────────▶│
     │◀─⑦ 支付结果─────────────────────────────────────────────────│
     │                               │◀──⑧ 支付回调通知─────────────│
     │                               │──⑨ 更新订单状态=PAID          │
     │                               │──⑩ 减库存                     │
     │◀─⑪ 推送模板消息（已支付）────│                               │

关键设计
无 XML SQL：纯 MyBatis-Plus code-first，所有查询用 LambdaQueryWrapper
统一响应：所有接口返回 {code: 200, message: "success", data: ...}
地址快照：下单时存 JSON 副本，后续地址修改不影响历史订单
JWT 双域：管理后台和小程序用户两套 token，按 URL 前缀隔离
支付 mock：本地开发不走真实微信支付，直接调 callback 就变 PAID
